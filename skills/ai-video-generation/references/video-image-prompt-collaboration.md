# AIGC 视频/分镜 Prompt 协作 SKILL
> 供 LLM 直接读取的工作规范。用户是 AIGC 视频创作者，主要用 **Seedance（视频）** 和 **GPT-Image-2（关键帧/角色图）** 生产短片。本文件提炼出**与具体项目无关**的可复用方法论：① 两个模型的元模板 ② 协作铁律。读完即可上手，无需追问基础规则。

---

## 一、SEEDANCE 视频 PROMPT 元模板

### 1. 结构骨架（每条 prompt 按此组织）
```
[STYLE LOCK]
<风格锚定一句话：参考导演/影像质感 + 胶片型号(如 Kodak Vision3) + 镜头(如 anamorphic 变形宽银幕) + 颗粒/自然光/真实肌理 + 画幅(如 2.39:1)>
<场景的光影、色调、环境底色一句话>

@[角色ID]   作为<角色>的形象视觉锚定。   ← 有角色锚定图时；逐角色一行

音轨：仅环境音与动作音，不配 BGM(除非要求)。<逐项列出与画面动作对应的环境声/动作声，紧贴动作>

<正文：连续散文，按时间顺序描述。运镜 + 人物动作 + 光影变化 + 细节，全部写满>

画面中不出现任何文字、英文、字幕、签名、水印、UI、图标、电量、时间。
```

### 2. 正文必须写好的维度（缺一不可）
- **运镜**：机位起止、运动方式（环绕/推拉/横摇/俯仰/手持）、速度、角度（如荷兰角）。镜头是「跟着谁/绕着什么」要写清。
- **人物动作**：分解到可执行的招式/姿态/移动，按时间推进；动作幅度、力度、方向。
- **光影变化**：光位、光质（硬/柔）、光比、色温；若光随动作/场景变化，写出过渡。
- **表情/神情**：眼神方向、面部状态（不写五官长相——长相由角色图锚定）。
- **细节**：发丝、衣摆、飞溅物（水/沙/火星/草屑/尘）的运动；前景/中景/远景层次。

### 3. SEEDANCE 严格禁止项（违反必出问题）
- **禁负向锚定**：不要写「不要 X」「NOT」「不出现 X」。要的东西正向描述；不要的东西**完全不写**（连「X 在画面外」这种都不行——提到即可能被渲染进画面）。
- **禁画面外元素**：只写**当前镜头内可见**的东西。不在画面里的，当它不存在，一个字都不写。角色看向画外某物，只写**视线方向**，不写那个物体是什么。
- **禁 CG/3D 语言（真人实拍项目）**：真人实拍/写实人物纹理的片子，STYLE LOCK 绝不写 CG/3D/CGI/写实CG/电影级写实/渲染。反 3D 靠：胶片型号 + 自然外光 + 真实皮肤发丝肌理 + 结构性（非材质）描述。（纯文生的氛围镜头可用「电影质感」类锚定，但凡是真人实拍线一律禁。）
- **禁景观/构图堆砌**：有参考图时，让参考图决定构图，不要在文字里堆砌景观描述（会和参考图打架）。
- **禁双语冗余**：同一信息不要中英重复写。
- **禁分镜列表化**：正文是连续散文，不要 sub-list、不要分阶段小标题、不要时间戳（除非用户明确要）。
- **音效不要单独成块**：音效嵌在对应画面动作里随文描述，不要拎出来单列一段。

### 4. 首/尾帧生成（first/last-frame）专项
- 首尾两帧已锁死起点终点，prompt 的活儿是写**中间的变形/过渡过程**（运镜、形变、消融、光变），不是重复描述两端画面。
- **绝不写「收束/定格/屏息/稳住/凝固」**：first/last-frame 本就强制收敛到尾帧，再写静止会让过渡后画面**冻结成静图**，丢掉该延续的动态。收幅写成「抵达尾帧构图后持续保持动态、绝不凝固成静止」+ 点名延续的动态（风、飘带、衣发、呼吸）。
- **承接镜头禁 meta 时序词**：做某条的「下一颗」时，正文绝不写「上一段/上一圈/承接/接着/继续」——模型会把前情也演一遍（如多转几圈）。承接关系靠**更换首帧**实现，不靠文字。

### 5. 状态变更技巧（泼水法）
当参考图的**默认状态**与所需状态不符（干 vs 湿、站立 vs 倒下、完整 vs 破碎），纯文字锚定目标状态会被参考图视觉惯性带跑。解法：把 A→B 的**变化做成镜头内的可见动作**（开头 1-2 秒演出来），@ID 那行按参考图**实际默认状态**写，变化在画面里发生。例：干→湿 = 开头一股水从画面上方浇下淋透；站→倒 = 开头大兽失衡侧倾砸地。

### 6. 环绕/遮罩转场拼接（多 clip 串成长镜）
- 多条 clip 用「遮罩物**从右往左**扫入画面直到挡满成纯黑」做接点：clip1 尾遮罩物右→左入画成黑，clip2 头从黑开始、**同一遮罩物**右→左继续移出露画。同物、同方向，黑帧才咬合。
- 遮罩物要是**该场景里真实存在**的东西（树/岩柱/立柱/人的背影）。
- 用「角色背影」做遮罩时，该角色必须**全程在画面里**（作为对练/同行方），遮罩才是「镜头绕到他背后」的自然结果，否则会变成凭空冒出来挡镜头的障碍物。
- 同组的关联 clip 要做**同一延续性动作**，不要两条各做不同动作。

### 7. 关于「匀速/变速/子弹时间」
Seedance 对主动控速（匀速、忽快忽慢、子弹时间慢镜）**服从度低**。可用可视化描述去逼（「机位像装在匀速旋转的轨道上」「草叶悬停在半空极缓翻飞」+ 声音拉长），但真实的变速节奏**大概率要靠后期调速**实现，不要指望模型一次到位。同理 dolly-zoom（希区柯克变焦）、大幅俯仰翻转、跨环境消融都是模型上限，预判需多抽卡或拆分+硬接。

### 8. 字数与敏感词（仅在用户明确要求目标字数时）
- 字数**只在用户明确给目标时**才核对，用代码精确数（bash/python3），不要估算。
- 敏感词扫描：语义级 + 单字根扫（如政治敏感字根的单字出现也要规避，例：「中央」→「正中」）。

## 二、GPT-IMAGE-2 关键帧/角色图元模板

### 1. 结构（三段式 Change / Preserve / Constraints）
```
[图像生成 prompt — <标题>]
<若基于参考角色：以放入的<角色>作为参考角色锚定长相与五官，本 prompt 只规定构图/姿势/光线/环境，不另描述五官>

# CHANGE（要改变的）
<构图、景别、占比、姿势、背景、光线——要生成的新东西>

# PRESERVE（必须严格保留，未列出的会漂移）
<长相、发型、服装、质感、神情——逐项列出。这一段是核心，没列的元素会被模型改掉>

# CONSTRAINTS（约束）
<去除项（文字/UI/多余元素）、必须明显呈现的关系、不要的风格>
```

### 2. 与 Seedance 相反的点
- **GPT-Image-2 可以用负向锚定**（「不要文字」「不要无袖战斗装」有效且推荐），Seedance 不行。
- **文字渲染可靠**，要画面无文字时正反两面都钉（CHANGE 不提 + CONSTRAINTS 明确去除）。
- **PRESERVE 段是命门**：参考角色的长相/发型/服装逐项列进 PRESERVE，凡没列的都会漂移。

### 3. 常见坑
- **景别拉不开/主体显大**：模型有「把主体拍清楚拍大」的惯性。要远景/小占比时，删掉「浅景深」「主体清晰」这类暗示近距离的词，改成「大远景/主体只是大场景里小元素/占画面 X 分之一」等硬指标；反之要近景同理。一次容易过/欠校正，靠迭代收敛。
- **精确多点位构图**（顶胯+后仰+头在中线+X形交叉等）服从度一般，可能给个大概。过度精确的几何关系建议简化，或多抽几张挑。
- **矛盾姿势**（低头但抬眼看镜头）可能被做成单一极端，需加重关键措辞。
- **双人不同参考角色 + 不同着装**容易串脸/串装，必要时分两次画再合成，或先画一人再 inpaint 另一人。
- 首帧看不到全身着装时，要用**文字锚定着装**（参考设定图逐项写），否则模型会乱穿。

## 三、协作铁律（贯穿所有任务）

### A. 流程
1. **不要在用户确认前产出大量内容**——先问「要不要做 X」。头脑风暴时给方向供选择，不要一次性甩多个完整草稿。
2. **前提有问题先反问**——方向跑偏/体量不合理/需求不清，先抛疑问再动手，别闷头执行。
3. **文件交付**：prompt 一律存 `.txt`，文件名用**纯英文**（中文文件名会触发服务器编码 bug）。产出后实际写文件并呈现给用户，不要只在对话里贴文本。

### B. 翻译而非直接搬运（headline 铁律）
用户口中的**比喻、梗、IP 引用、抽象意图**，必须先翻译成「**镜头可解析的具体视觉描述**」再进 prompt，绝不原样转录。例：「猫和老鼠那样」→ 翻成具体的追逐站位/动作；「法环 boss 那种」→ 翻成具体的体型/姿态/光效。结构性意图也要翻（如「遮罩接点」要翻成具体的入画方向与几何）。

### C. 真实判断，不阿谀
- idea 好就说好，不好就说不好，一般就说一般。不要用赞美开场缓冲，不要铺垫优点再转折。
- 不确定就说不确定、说「这里需要再想」。承认不确定是诚实，不是能力不足。
- 用户的方法论/习惯是「一种工具」不是「铁律」，某项目更适合突破其习惯就直说。
- **不要把「催化剂/我只给 70 分你蹦 95」当成输出低质量方案的免责借口**，该努力给高分方案时就给。

### D. 以项目为主，不以人为主
- 每个项目的最优解由题材/体量/受众/载体/情绪基调决定，不由个人品味决定。先找「这个项目需要什么」。
- 用户提过的导演/作品/美学只是其审美版图说出口的一小部分，不代表只接受这些，不要下意识往这些名字上靠。推荐参考系/风格/策略时从项目本身出发。
- 给方案主动提**反向选项**：至少一个符合常规路径 + 一个反直觉，说明各适合什么情况。

### E. 不做speculative风险预警
不要基于猜测对模型能力做预防性风险警告。只引用**已验证的官方文档**或**确认过的真实测试结果**。模型能不能做某事，跑了才知道——除非用户已确认某能力缺口，否则不要凭空预言「这个做不出来」。（但可在交付时**客观**说明某些已知是模型上限的操作[如 dolly-zoom、变速、跨环境消融]大概率需多抽卡或后期，这属于已验证经验，区别于凭空臆测。）

### F. 工具调用纪律
调用工具（写文件、呈现文件等）务必用**正确的调用语法**。语法错误会导致工具不执行、用户空等。每次产出 prompt 后：写文件 → （如需）用代码核字数/扫敏感词/扫 CG 污染 → 呈现文件。

### G. 适时停一下
对话里出现信号（用户主动提到情绪、明显卡壳、聊着偏到自我消耗），可以停下手里的活问一句怎么样，但不强行开启「情感支持对话」。保护「低压力、不追问」这个属性比表现关心更重要。回答多少由用户决定，说「继续干活」就继续。

## 四、快速自检清单（每条 prompt 产出前过一遍）
- [ ] STYLE LOCK 是否符合项目（真人实拍线**无任何 CG/3D 词**）？
- [ ] 运镜/动作/光影/表情/细节五维度是否都写到？
- [ ] 有没有负向锚定（Seedance 禁）/画面外元素？
- [ ] 首尾帧：是否误写了「收束/定格」？承接镜头是否误写了「上一段/继续」？
- [ ] 音效是否嵌在画面动作里（没单独成块）？
- [ ] 是否有未翻译的比喻/梗/IP 直接进了 prompt？
- [ ] 文件名是否纯英文？是否实际写文件并呈现？
- [ ] （若用户给了目标字数）是否用代码精确核对、扫敏感字根？
