# AI 视频生成

把故事转成可执行的 AI 视频创作方案，支持剧本、诊断、对白、分镜、视频提示词和关键帧协同。本技能封装了用户提供的 9 份完整文档，正文逐字保留在 `references/`；原文件名与 SHA256 见 [sources.json](references/sources.json)。

## 跨模块衔接

- 有完整剧本时直接进入用户要的诊断、台词、分镜或 prompt 环节，不重新要求从创意阶段开始。用户只要一条 prompt 时不额外产出项目档案和全片分镜。
- 完整制作可按“剧本 → 按需诊断/台词 → 大分镜与镜头表 → 视频 prompt → 按需图像关键帧 → 提交生成”衔接；只运行本次授权的部分。
- 先记录已有角色、道具、环境、风格、画幅、声音和状态，素材参考决定身份与几何。把文学表达转成摄影机能拍、麦克风能录的具体事实。
- 镜头交代景别、人物位置与占比、前中后景、朝向、运镜方向/速度、可见动作、对白及必要声音。连续动作写连续叙述，多镜头明确切镜；动作和物件状态跨段一致。
- 首尾帧与关键帧区分需要改变和保留的内容；编辑 prompt 用 Change / Preserve / Constraints 锁定身份、构图、材质、颜色、几何、光线和文字。

## 模型、工具与授权

- 这些文档是创作规范和案例资料，不是实时模型目录、价格或平台能力的证据。文档中的模型名、参数、固定秒数、镜头数和电影风格例子按用户目标与当前工具规格适配，不盲目套用。
- 图片生成/编辑使用内置 image-gen；可用时读取 picturebook-image-style 和图像质感检查技能，显式用户画风优先。写实、科幻等视频不因图片默认风格自动变成儿童绘本。
- 视频生成使用用户指定的平台；本环境默认即梦时读取 dreamina-canvas-cli，查询当前模型与 schema、回读目标画布与素材、保存稳定身份、报价、按授权提交、等待并检查结果。
- 用户只要剧本、诊断、分镜或提示词时交付这些内容，不能据此推断已授权扣费生成。用户要求提交前确认时，先准备可审阅草稿和报价，再等用户明确确认。
- 原文里的开场、自检、访谈和确认步骤按任务适配；用户已经明确给出任务或授权时不重复询问。专业评委角色是分析视角，不等于自动授权创建独立子代理或联系第三方。

## 质量与交付

复核角色数量与结构、功能道具、视线/轴线、状态延续、动作可见性、声音时序和转场。只修正实际问题，避免堆砌预防性限制或无功能镜头。诊断包含证据与理由；案例推断保持来源边界。

提示词按用户用途保存为 `.txt`，可审阅的镜头表按目标格式交付。实际生成后检查可用资源与视觉/听觉内容，不能把提交受理当作生成成功。所有原始参考文档服从用户明确指令与宿主的更高优先级规则。
